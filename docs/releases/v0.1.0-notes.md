# Ethereal Logic Platform v0.1.0 — 发布说明（草案）

> **状态：草案（DRAFT），尚未发布。** 本文件是 `E1-DMO3` 的本地产物；发布动作（打 tag、创建 GitHub Release、公开仓库、上线文档站）属于维护者的外部步骤。

- 目标里程碑：`E1-DMO2`（双镜像热切换）+ Phase 0–3 的仿真验证闭环
- 验证方式：全部结论来自本仓库可复现的仿真/形式化/模型证据（每项附报告）

## 这个版本是什么

把 Docker 的 **image → container → orchestration** 心智模型映射到 FPGA 域，并在一个控制面里统一：

- **Ethereal（FPGA 侧）**：**虚拟可重构 overlay fabric**（"FPGA 里的 FPGA"）。用户逻辑被编译成 fabric 的**配置数据**（非厂商 bitstream）⇒ 跨厂商二进制兼容、微秒–毫秒级热切换，且**重配置行为本身可被 Verilator 验证**（原生 DPR 按 AMD UG909 无法仿真）。
- **Astral（固件/应用侧）**：嵌入式 MCU 的容器运行时路径。两者经 **Type-F 容器**汇合。
- **管理核心**：fabric 内的 **NEORV32 RISC-V 软核 BMC**（小设备退化为寄存器级 mFSM），两者暴露**同一套 EMRI 寄存器 ABI**，`ethctl` 对二者透明。

| 配置期望-CRC 门 + 区域锁矩阵 | ADR-019；`LKM_STATUS`/`LKM_CMD`；`tb_lock_matrix` + BMC 端到端 **91 ok / 0 FAIL** |

### eth_rv（RV64IMC 应用核，C14）

- 5 级 RV64IMC + Zicsr + M/S/U 特权模型 + RVFI 轨迹端口；**对 Spike 逐提交比对零分歧**（8 个语料程序，拍路径与 AXI/DRAM 路径各一遍）
- 裸机 `hello, eth_rv!` 经 **16550 子集 UART**：15 帧 × 160 周期、0 帧错（位时序被断言）
- **access-fault 陷阱**（D 口/取指口）与错误响应：以 Spike 为裁判先确认 13 组语义，负控覆盖"卡死"与"静默成功"两种失败模式
- RVFI 轨迹契约形式化（k-induction + 11/11 cover）

### Astral 侧（降级路径）

- **MCU 脚本部署**：Flash 常驻脚本（CRC32 门 + 硬预算）+ 无 malloc 解释器 + Ed25519 验签部署到区域；`tb_bmc_script` PASSED，含脚本损坏/签名篡改两条拒绝路径
- ⚠️ WASM 容器验收仍未完成（本环境无 Zephyr/WAMR 运行时）

## 不在本版内（明确边界）

- 任何 **厂商工具链**产物（Gowin/AMD bitstream、AE350 硬核 —— ADR-013 已弃用）
- **原生 DPR**（Gowin 无用户级 PR，ADR-001 走 overlay）
- 真实硬件上板结果（全部为仿真/形式化证据；上板属 Phase 1+ 的自托管 runner 工作）
- 安全隔离保证（v1 防事故、不防攻击 —— 见 `memory/04` 风险 R8）

## 安装与快速开始（发布后）

```bash
git clone https://github.com/BaiTian6641/Astral_Platform.git
cd Astral_Platform
export PATH=$HOME/oss-cad-suite/bin:$PATH
make lint          # 项目 RTL lint（应全绿）
make test-model    # 金模型 pytest
make test-sv       # SystemVerilog TB（含 Verilator --timing 的 BMC 端到端）
make verif-rv      # eth_rv 对 Spike 的 DiffTest
```
