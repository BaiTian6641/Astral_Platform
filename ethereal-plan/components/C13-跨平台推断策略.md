# C13 · 跨平台推断策略（Inference-First · ADR-017）

> 性质：横切策略文档，约束**全部** RTL 组件（C01-C12）。优先级仅次于规范冻结。
> 触发：用户决策（2026-07）——先用 Verilator 验证、核心全部自研、禁用厂商 IP 核；DSP/RAM 以行为级描述交各平台 EDA 推断优化。

## 1. ADR-017：推断优先（Inference-First）策略

**背景**：厂商 IP 核（UNISIM/UNIMACRO、Gowin 原语库、Quartus megafunction）有三个硬伤：(a) 仿真模型为时间步仿真器编写且部分加密，**Verilator 无法（或极难）读取模拟**——这直接堵死"Verilator 先行验证"的路线；(b) 锁定单一平台，与跨厂商承诺冲突；(c) 每个平台的 DSP/RAM 架构不同，手写原语实例意味着每个平台维护一份代码。

**决策**：平台全部自有核心（fabric、Shell、BMC 周边、代理、Service Tile）采用**行为级 RTL 描述**——用运算符号（`*`、`+`、`-`）与标准存储编码模式描述硬件行为，**由各平台 EDA 的推断引擎映射到最优物理资源**（DSP 块/BSRAM/分布式 RAM）；平台差异通过**统一属性层 + 每平台微调约束**吸收。禁止在自有核心中实例化任何厂商 IP/原语，例外清单见 §4。

**依据（2026-07 交叉验证）**：

| 证据 | 来源 |
|---|---|
| GowinSynthesis 官方支持 DSP 推断：device-independent RTL 的乘法/部分加法自动置换为 DSP；支持有/无符号、同步/异步、乘法链加、累加、预加、寄存器吸收（输入/输出/bypass）；`syn_dspstyle=dsp|logic` 逐对象控制 | SUG550E §4.3 |
| GowinSynthesis 官方支持 memory 推断映射与逻辑资源平衡 | SUG550E §2 |
| Yosys `synth_gowin` 经 `memory_libmap` 推断 lutrams/brams（开源链路同样成立） | Yosys 文档 |
| Vivado：signed 运算、充分流水、禁 set/异步复位、对齐 DSP 位宽（27×18），即可从行为级代码推断单/多 DSP 及级联、寄存器吸收；`use_dsp` 属性微调；多 DSP 大乘法可由 retiming 自动分解流水 | UG901/UG949 |
| Intel Quartus：完整的乘法/乘加/存储推断编码风格指南 | Quartus II Handbook §6 |
| 厂商仿真库（UNISIM 等）面向时间步仿真器、部分加密；社区标准做法是"行为级描述，PLL 等必需原语留在 Verilated 边界之外" | Digilent 论坛（D. Gisselquist）、GHDL 文档 |
| **原生 DPR 在原理上不可仿真**：UG909 原文 "Partial reconfiguration itself cannot be simulated"；厂商 workaround 仅为 persona mux 复用 | UG909 / DPR 综述（ACM Computing Surveys） |

**后果**：(+) 全部自有逻辑 Verilator 可验证；跨平台只需维护一套 RTL + 每平台一个属性/约束文件；EDA 换代自动受益。(-) 对推断质量的控制弱于原语实例，必须用"推断验证套件"（§6）持续核对各平台的推断报告；极端性能场景保留"例外通道"（§4）。

## 2. 推断模板库 `eth_inf_*`（平台自有、厂商无关）

所有自有核心只准实例化以下模板；模板内部是行为级编码模式（这些模式是三家工具都承诺识别的"公约数"）。

### 2.1 `eth_inf_dsp_mac`（定点乘加核）

```systemverilog
// 行为级 MAC：signed + 输入寄存 + 输出流水 + 同步复位、无 set
// 推断目标：Gowin DSP / DSP48E2 / Intel DSP —— 由属性层微调
module eth_inf_dsp_mac #(
    parameter int AW = 27, parameter int BW = 18, parameter int LAT = 3
) (
    input  logic                     clk_i,
    input  logic                     rst_ni,      // 同步复位在内部生成
    input  logic                     en_i,
    input  logic signed [AW-1:0]     a_i,
    input  logic signed [BW-1:0]     b_i,
    input  logic signed [47:0]       c_i,         // 加数/级联入
    input  logic                     acc_i,       // 1=累加 0=c_i
    output logic signed [47:0]       p_o
);
    // 实现：a_r/b_r 输入寄存 → mult <= a_r*b_r → p <= acc? p+mult : mult+c_r
    // 全流水 LAT 级；rst 同步、只清 0（set 会阻挡 DSP 映射，UG949）
endmodule
```

**编码红线**（三平台共同要求）：signed 声明；运算数对齐目标位宽（≤27×18 单 DSP）；充分流水；**禁止 set（复位值只能为 0）**；**禁止异步复位**；需要保留独立寄存器时用 `KEEP`/`syn_preserve`（两家语义一致）。

### 2.2 `eth_inf_ram`（块 RAM 模板）

```systemverilog
// 同步读块 RAM：read-first、字节写使能、可初始化
// 推断目标：BSRAM / BRAM36 / M20K
(* ram_style = "block" *)   // Xilinx 系；Gowin 由属性层映射 syn_ramstyle=block_ram
logic [31:0] mem [0:DEPTH-1];
always_ff @(posedge clk_i) begin
    if (en_i) begin
        if (we_i) mem[addr_i] <= (mem[addr_i] & ~be_mask) | (wdata_i & be_mask);
        rdata_o <= mem[addr_i];   // 同步读 → block RAM；read-first
    end
end
```

### 2.3 `eth_inf_lutram`（分布式 RAM 模板——eLUT 真值表的 v2 路径）

```systemverilog
// 异步读小 RAM：写同步、读组合 → 推断为分布式 RAM / CFU memory 模式
(* ram_style = "distributed" *)
logic [15:0] tt;
always_ff @(posedge cfg_clk_i) if (cfg_we_i) tt <= cfg_tt_i;
assign vout_o = tt[vin_i];        // 异步读 = LUT 行为本身
```

**这是 v1→v2 的关键发现**：eLUT 真值表的"LUTRAM 化"**不需要任何原语**——异步读 RAM 模式既是 Verilator 可仿真的普通 RTL，又会被 GowinSynthesis/Yosys/Vivado 推断为分布式 RAM/CFU memory 模式。原 C03 §6 的"原语 spike"因此改写为"推断验证实验"（§6），且**提前到 Phase 1 评估**（不再等 v2）。

### 2.4 `eth_inf_rom` / `eth_inf_fifo_sync` / `eth_inf_fifo_async`
ROM：常量数组+异步读；同步 FIFO：指针+`eth_inf_ram`；异步 FIFO：Gray 指针（C06 cdc_lib，纯逻辑无推断需求）。

### 2.5 属性分层（一套 RTL，N 个平台）

```systemverilog
// eth_config.svh —— 每目标一份，属性唯一出处
`ifdef TARGET_GOWIN
  `define ETH_DSPSTYLE /* synthesis syn_dspstyle="dsp" */
  `define ETH_RAMSTYLE /* synthesis syn_ramstyle="block_ram" */
`elsif TARGET_XILINX
  `define ETH_DSPSTYLE (* use_dsp = "yes" *)
  `define ETH_RAMSTYLE (* ram_style = "block" *)
`else // TARGET_GENERIC / VERILATOR：属性为空，纯行为
  `define ETH_DSPSTYLE
  `define ETH_RAMSTYLE
`endif
```

规则：RTL 中只写 `` `ETH_DSPSTYLE `` 宏；厂商专属语法集中在 `eth_config.svh`；宏展开后仍是合法 SV（Verilator 走 GENERIC 分支）。

## 3. Overlay 与 Verilator：可验证性声明（回答"能验证吗"）

**结论：能，而且是完全验证——这恰是 overlay 对原生 DPR 的被低估的优势。**

| 验证对象 | Verilator 中是否可验证 | 说明 |
|---|---|---|
| fabric 全部逻辑（eLUT/CLB/SB/CB/tile） | ✅ | 普通同步 RTL |
| **"重构"行为本身（OCC 写配置→虚拟电路改变）** | ✅ | 本质是寄存器/RAM 写——**原生 DPR 做不到**（UG909："Partial reconfiguration itself cannot be simulated"），因为那是器件物理行为；我们的"重构"是我们自己的逻辑 |
| 逻辑镜像 bit-true（c432/AES/FIR） | ✅ | 配置写入后跑黄金向量 |
| mailbox/OCC/SPI/I²C 协议 | ✅ | 含随机背压/故障注入 |
| BMC 固件协同（NEORV32 全仿真） | ✅ | NEORV32 原生支持 Verilator |
| blank/lock/看门狗状态机 | ✅ | 功能级断言 |
| 配置瞬态毛刺（模拟量行为） | ⚠️ 功能级替代 | Verilator 是**周期级二值仿真**：可断言"改写期间邻区输出逻辑值不变"（功能级无干扰），但**真实模拟毛刺（ns 级瞬态）不在其表达能力内**——该项由 blank-before-write 的结构性设计 + 上板示波器验证承担（S02 验证表述已按此修正） |
| 时序/Fmax | ❌ | Verilator 无时序概念；由厂商 STA + 上板实测承担 |
| 不可推断资源（§4） | ⚠️ stub | 行为桩验证接口协议，不验证物理特性 |

**工程含义**：Phase 0/1 的全部功能验收都可以在 Verilator 内闭环，硬件只做"物理确认"（时序、毛刺、推断质量）——研发迭代速度不受上板次数限制。

## 4. 不可推断资源：例外清单与仿真边界

| 资源 | 能否推断 | 处置 | Verilator 模型 |
|---|---|---|---|
| PLL / 片内振荡器 / DCS 时钟切换 | ❌ | `hal_clk` 薄胶合（C12 §2），唯一允许的原语区 | 行为 stub：`clkgen_stub` 直接输出时钟 |
| ADC（X 通道）/SYSMON | ❌ | `hal_adc` façade（C06 §3） | stub：可编程寄存器+伪读数序列 |
| SerDes / PCIe 硬核 | ❌ | P3+ 才用，独立 wrapper | 不在 v1 仿真范围 |
| Flash 接口 | ⚠️ 通用 SPI 可推断，但 MSPI 专用口需原语 | v1 走通用 SPI 控制器（推断）；MSPI 留例外 | SPI Flash 行为模型（开源模型可用） |
| IO 电气特性（电平/驱动/上下拉） | ❌（约束而非 IP） | `.cst/.xdc` 约束文件，RTL 零涉及 | 不涉及（引脚在仿真中是理想信号） |
| GSR/启动时序 | ❌ | base image 特性，不进自有 RTL | 不涉及 |

**边界规则**：上述原语只允许出现在 `hal/<vendor>/` 目录内的胶合模块；`verilator` 构建时使用同名 stub 替换（file list 级切换）。CI 门禁：**grep 检查 `hal/` 之外不得出现任何厂商原语名**（UNISIM/Gowin 原语/megafunction 名单维护在 CI 脚本）。

## 6. 推断验证套件（infer_check，CI 常驻）

**目的**：推断质量不受我们直接控制，必须持续实证。每个 `eth_inf_*` 模板在三个工具链上构建并自动核对推断报告：

| 检查 | Gowin EDA | Vivado | Yosys/nextpnr |
|---|---|---|---|
| dsp_mac → DSP 块 | 报告含 DSP 原语且 LUT 不爆 | utilization 报 DSP48 | stat 含 dsp 单元 |
| ram → BSRAM | BSRAM 计数符合预期 | RAMB36 | bram 单元 |
| lutram → 分布式 RAM | CFU memory 计数 | LUTRAM | lutram 单元 |
| 面积/Fmax 记录 | 入性能看板（S14） | 同 | 同 |

任一家推断失败（悄悄退化为 LUT 实现）→ CI 变红 + 报告差异。**这是"把优化交给 EDA"所必须支付的监督成本。**
