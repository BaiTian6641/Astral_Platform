# Phase 5 · 商业级演进（M24+，方向性）

> 目标：在**永远完整可用的开源核心**之上构建商业能力。前提判断点：Phase 4 结束时社区规模不足则继续深耕开源，不强行商业化。
> 本阶段为方向性规划，细节在 Phase 4 中期评审时重排。

## 1. 候选业务线

| 线 | 内容 | 依据 |
|---|---|---|
| 企业版编排 | 集群管理（多板池化调度，借鉴 ViTAL）、RBAC、审计日志、SLA 监控 | 开源核心不含企业治理能力 |
| 安全认证服务 | IEC 61508 / ISO 26262 预评估材料包；SEU 擦洗+健康监控+看门狗是差异化卖点（S07） | 工业/车载为"健康审计"付费 |
| 镜像仓库 SaaS | 托管 registry、CI/CD 模板（GitHub Actions 一键构建比特流镜像）、私有命名空间 | OCI 生态已打通（S09） |
| 厂商适配服务 | Gowin/国产 FPGA 官方适配、定制 Service Tile、参考设计授权 | 平台是厂商的软件生态补充 |
| LTS 与支持 | 年度 LTS 版本、SLA 支持、培训 | 开源项目标准商业模式 |

## 3. 治理与法律
- 许可证组合已定型（MIT / CERN-OHL-S / CC-BY-SA，ADR-005）；商业化前完成：商标注册、贡献者 CLA/DCO 审计、第三方依赖许可证审计（NEORV32 BSD-3、VPR O ACADEMIC？——注意：VPR/VTR 为 MIT；FABulous Apache-2.0 仅借鉴未并入代码，审计确认）；
- 考虑加入中立基金会（CHIPS Alliance / Linux Foundation）提升工业界信任。

## 4. 本阶段唯一硬性规则
**开源核心永远完整可用**——所有商业线都是增量，不是解锁。这是项目信誉的根基，也是对社区的承诺。
