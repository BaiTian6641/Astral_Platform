## 1. 是什么 / 做什么 / 重要度

应用处理器子系统是平台的**用户侧通用处理器**——类比 Zynq 的 ARM PS。它给最终用户提供
**可 boot Linux、全系统可达、可运行自定义固件**的计算能力，与 fabric（虚拟逻辑容器）、
BMC（管理面）并列为一等公民。

三要素（**全部自研**，CERN-OHL-S-2.0）：
1. **自研可配置 RISC-V 核心集群 `eth_rv`**（目标 RV64 / RVA23 方向，≤4 核；用户可配 RV32/RV64、
   单/多核、实时嵌入优化），挂在**标准 AXI4 插座**后可插拔（用户也可插任意满足插座的核心）；
2. **自研 DMA 子系统**：一个**多通道 DMA `eth_dma_mc`**（通用数据搬运）+ 一个 **2D 图形 DMA
   `eth_dma_2d`**（ND-strided + blit/fill/ROP 像素处理）；
3. **封装式 DRAM 组件 `eth_dram_ctrl`**：标准 AXI4 内存从机接口，按目标封装（Zynq-PS /
   GW5-hard-DDR3 / 未来自研 DDR 控制器，tapeout 目标）。

**为什么重要**：没有它，平台只有"管理面（BMC）+ 可配置逻辑（fabric）"，用户无法跑真正的
软件栈。有了它，Ethereal 成为完整的"FPGA 容器主机 + 通用处理器"平台——这是从"FPGA 虚拟化"
走向"FPGA 操作系统"的关键一跃。

## 2. 核心集群（可配置 + 可插拔）

### 2.1 标准 AXI4 集群插座（冻结接口，核心可换）

插座是唯一契约（ADR-016 `bmc_core` 模式在应用域的推广）：

| 接口 | 规格 | 用途 |
|---|---|---|
| Master port(s) | AXI4 (+ATOP 原子，SMP 必需) → 系统 `axi_xbar` | 访存/访外设 |
| Interrupts | PLIC + CLINT 作为 AXI MMIO 从机 | Linux 标准中断 |
| Debug | JTAG/cJTAG DTM 引脚（可换） | GDB |
| Config 描述 | `core.yaml`（XLEN/核数/MMU/H/V/缓存/总线宽） | 驱动生成 wrapper + device tree |

**核心可换是结构性的**：SoC 胶合只依赖插座，不依赖具体核心。**我们的自研核心 `eth_rv`
插在这里**；用户也可插任意满足插座的核心（CVA6 / 未来的 RVA23 核心）。

### 2.2 自研核心 `eth_rv`（CERN-OHL-S-2.0）— RVA23 方向，分阶段

微架构（首核）：**顺序、单发射、5-6 级流水线**（CVA6 验证过的模板），**不做 OoO**。
尽早上 Linux（逼出 Sv39 + 中断 + 异常正确）。**验证 >> RTL** —— 第一天就上
**DiffTest 锁步 co-sim vs Spike**。

**分阶段（RVA23 方向 —— 延后两个进度杀手 Vector + Hypervisor）：**

| 阶段 | 核心 | 启动 | 工作量(1-2人) |
|---|---|---|---|
| **RV-B** | RV64IMC（无 MMU） | bare-metal / FreeRTOS over UART | 6-12 人月 |
| **RV-C** | RV64GC + **Sv39 MMU**（+ TCM/CLIC 选项） | **Linux** | +6-12 人月（~1.5-2 人年累计） |
| **RV-E** | RV64GC 2-4 核集群，共享 L2 + 相干 | SMP Linux | +4-8 人月 |
| **RV-F** | + **Hypervisor (Sha)**，再 + **Vector (V 作协处理器，CV-X-IF 式标准接口)** + Z\* 扫尾 | RVA23 完整 | +1-3 人年（Vector 主导） |

- **GW5 验证档（维护者定）：单核 RV64 RVA23 方向 = RV64GC + Sv39（阶段 RV-C）**。
  Vector/Hypervisor 延后——真 RVA23 完整核是 Phase-2/tapeout 目标，非 Phase-1 阻塞。
- **Vector 策略**：作**协处理器**经标准扩展接口（Ara/Vicuna 模型），不入主流水线。
- **DV 参照（学习非抄袭）：** CVA6（RV64GC+Sv39+H 结构，>50 参数）、Rocket（流水线）、
  Ara/Vicuna（Vector 协处理器 + CV-X-IF）。RTL 100% 原创。

### 2.3 可配置核心生成器（`app_cluster.sv`，同 fabric_gen 约定）

单一冻结参数包 `eth_core_config_pkg`：`XLEN{32,64}`、`CORE_COUNT{1,2,4}`、
`HAS_MMU/H/V/FPU/CLIC`、`ICACHE/DCACHE/TCM` 大小。薄 Python 生成器发 generate 块
（数据通路手写可读，只 generate 实例化/连线）。**全验证只 bless 2-3 个配置**（CVA6 纪律）。

### 2.4 实时嵌入优化

尚无批准的 RISC-V 实时 profile；关键实时块：
- **CLIC**（Core-Local Interrupt Controller）：向量化、优先级、**嵌套抢占 + 尾链** →
  低且确定的中断延迟（vs PLIC 平坦模型）。CLIC 是**草案**（未批准）——按概念设计、模块化可换
  （Linux 默认仍 PLIC）。
- **TCM（ILM/DLM 紧耦合存储）**：单周期确定访问（无 cache miss 抖动）+ 顺序流水线 = 可预测 WCET。
- 双人格：**Linux 可跑（Sv39, PLIC）** 与 **实时可嵌（TCM, CLIC, 可无 MMU）**——同插座，配置选。

### 2.5 GW5AST-138 可行性（诚实）
- **单核 RV64GC + Sv39（顺序，~30-50K LUT 估）装得下**（留 overlay 预算）= 验证档。
- 4 核 RV64 集群与 Vector 装不下 138K → Zynq US+ / tapeout。DMA 子系统（§3）装得下。

## 3. DMA 子系统（处理器子系统内，自研可配置）

| 引擎 | 基座 | 可配置项 | 用途 |
|---|---|---|---|
| **多通道 DMA `eth_dma_mc`** | 自研（结构参考 PULP `iDMA` / Xilinx AXI DMA / ZipCPU AXI DMA） | 通道数/总线宽/缓冲深度 | 通用数据搬运：app-cluster(Linux dmaengine)、BMC(<10ms 热替换帧 DMA)、region 数据 |
| **2D 图形 DMA `eth_dma_2d`** | 自研 ND-strided 地址引擎 + 自研 SV blit/fill/ROP 级 | HSIZE/VSIZE/STRIDE（VDMA 兼容）；ROP/blend/rotation 构建开关 | 2D 块/跨行/tile 搬运 + blit/fill/ROP/alpha-blend/色彩转换/旋转；**Service-Tile 级加速器（S11）** |

- **多通道 DMA**：描述符链表 / scatter-gather（src/dst/len/ctrl, SOF/EOF, IOC 中断）、
  通道仲裁、寄存器直驱 + SG 模式、可选数据重对齐、64 位地址、AXI4 主（+可选 AXI4-Stream）。~2-8K LUT。
- **2D 图形 DMA**：ND-strided 地址引擎（2D=N2，参考 PULP `tensor_ND` 模型）做**搬运**，
  + 一小段**自研 SV blit/fill/ROP 流水线**做**像素操作**（无许可宽松开源 BitBLT；DB9100 专有）。~3-8K + 1-3K LUT。

## 4. 封装式 DRAM 组件

SoC 只经标准 **`eth_dram_ctrl` AXI4 内存从机接口**访 DRAM；实现按目标：

| 目标 | 实现 | 状态 |
|---|---|---|
| Zynq US+ | Zynq PS DDR（AXI HP 口） | 封装于 `hal/zynq/glue/` |
| Gowin GW5 | GW5 hard-DDR3 PHY+控制器 IP | 封装于 `hal/gowin/glue/`（ADR-017：非可推断块，附 **Verilator stub**） |
| Tapeout（未来） | **自研开源 DDR 控制器** | **预留插座**（AXI4 从机接口即契约） |

- 解耦"用哪个 DDR"问题：应用集群永远看到同一 AXI4 内存从机；目标 HAL 提供它。
- GW5 hard-DDR3 封装是**硬件 bring-up 任务**（维护者）；在此之前 GW5 应用集群跑
  **无 DDR 配置**（BootROM + 片上 SRAM + 可选外部 SPI-flash/PSRAM rootfs）。
- **Verilator 可验证性保留**：每个 DRAM 实现附行为级 AXI4 内存 stub（ADR-017）。

## 5. Boot 与软件栈

```
BootROM(BSRAM) → OpenSBI(M-mode) → U-Boot(S-mode) → Linux kernel(S-mode)
```
- hartid + DTB 指针经 `a0`/`a1`（标准 RISC-V boot ABI）；`core.yaml` 生成 device tree。
- PLIC + CLINT 作为 AXI MMIO 从机（Linux 标准驱动）。
- 自研核心 `eth_rv` 的 boot 流：自研 BootROM + 上游 **OpenSBI**（BSD，固件，非 RTL IP）
  + U-Boot + Linux。工具链/固件复用上游开源（GCC/OpenSBI/U-Boot/Linux 均为软件，非我们
  重写的 RTL）；我们自研的是**硬件核与 SoC**。

## 6. 分阶段（工作量估，1-2 工程师，诚实幅度）

> 诚实幅度：**AXI + DMA = 人月级；RV64 核 = 人年级；RVA23 完整（V+H）= 多年团队级。**
> 核作为**工程**规划，不是任务。

| 阶段 | 范围 | 工作量 |
|---|---|---|
| **A — `eth_axi`** | 自研 AXI4-Lite + AXI4-Stream + 小 AXI4 交叉开关，**形式化验证**（skid buffer、ID 路由、decode-error slave），iverilog 兼容 | 1.5-3 人月 |
| **B — `eth_rv` RV64IMC** | 顺序 5-6 级 RV64IMC（无 MMU），bare-metal/FreeRTOS over UART，跑在 `eth_axi` 上；DiffTest vs Spike | 6-12 人月 |
| **C — `eth_rv` RV64GC + Sv39** | +FPU(D)+C+Sv39 → **boot Linux**（**GW5 验证档**） | +6-12 人月 |
| **D — `eth_dma_mc` + `eth_dma_2d`** | 多通道 SG DMA + 2D blit/fill/ROP（与 B/C 并行） | 2-4 人月 |
| **E — SMP 集群** | 2-4 核，共享 L2 + 相干，每核 CLIC | +4-8 人月（Zynq US+） |
| **F — RVA23 完整** | +Hypervisor (Sha)，+Vector（协处理器），Z\* 扫尾 | +1-3 人年（tapeout 目标） |
| **G — Tapeout** | 自研 DRAM 控制器（或控制器+授权 PHY） | 工程级 |

**首个里程碑（bring-up 载具）：** 阶段 A（`eth_axi` 形式化验证）+ 阶段 B（`eth_rv`
RV64IMC 裸机 hello，GW5AST-138 上），在现有 Verilator/iverilog 流程内。~9-15 个月
兼职可达；端到端打通自研工具链并产出可配置生成器骨架（复用于 RV64GC → SMP → RVA23）。
