# S09 · 镜像格式与仓库（ethimg / OCI）

> | 属性 | 值 |
> |---|---|
> | 仓库 | ethereal-tools（ethimg）/ ethereal-spec（RFC-001）/ ethereal-images |
> | 许可证 | MIT / CC-BY-SA-4.0 |
> | 重要度 | ★★★★☆（生态的载体） |
> | 关联 | ADR-011；任务 E1-RUN1、E3-REP1；上游 OCI image/artifact 规范 |

## 1. 是什么 / 做什么 / 重要度

定义平台的四类镜像（base / logic / service / bundle）的**文件格式、清单语义、签名机制**，以及镜像的分发设施（`ethimg` 工具 + 镜像仓库）。logic image 是用户日常产物：fabric 配置帧 + manifest + interface + capabilities（见 v2.0 蓝图 §5.1）。

**为什么重要**：格式是生态的契约——一旦第三方开始发布镜像，破坏性变更代价巨大，所以 RFC-001 要"最小可用但前瞻预留"，Phase 2 冻结 v1.0。兼容 OCI artifact 则能白嫖整个云原生 registry 生态（GitHub Packages、 Harbor 都能存镜像）。

## 2. 大体规划

### 2.1 logic image 结构（tar 包，`.eth`）

```
aes128.eth (tar)
├── manifest.yaml      # name/version/digest/ed25519 signature/author
├── interface.yaml     # EBI ABI 版本、虚拟 IO 需求、中断、时钟需求
├── capabilities.yaml  # IO/服务权限声明（S10 校验依据）
├── resources.yaml     # eLUT/MEM-T/DSP-T 需求与上限（region 匹配依据）
├── health.yaml        # 看门狗周期、restartPolicy
├── targets/
│   ├── efab-1.0.frames     # fabric 配置帧（S03 bitgen 产物）
│   └── efab-1.0.meta.json  # 帧统计/占用报告
└── docs/README.md
```

**多架构设计**：`targets/` 以 fabric 架构版本索引（非器件型号！）——overlay 路线的红利：一个 target 天然跨厂商。若未来原生 DFX 镜像加入，则增加 `xczu*`/`gw5a*` 器件 target，结构同构（对齐 Docker manifest list 体验）。

### 2.2 签名与信任

Ed25519：私钥签名 manifest digest；公钥指纹列入平台信任库（BMC 固件配置）；**v1 强制验签（Phase 2 SEC1 起拒绝未签名/签名失败镜像）**。密钥管理：单机自签起步 → Phase 4 引入简单 CA/团队公钥集。

### 2.3 仓库

- **v1（Phase 1）**：Git 仓库 + 静态索引（ethereal-images 官方镜像 + 示例）；
- **v2（Phase 3，E3-REP1）**：OCI Registry 兼容——`.eth` 作为 OCI artifact（自定义 media type `application/vnd.ethereal.image.v1+tar`），`ethctl push/pull` 指向任意 OCI registry；官方索引服务提供搜索。

## 3. 详细规划与阶段检查点

## 4. 验证与里程碑验收

**方法**：格式 round-trip fuzz（随机字段/边界值）→ 签名攻击用例（篡改/替换/重放）→ 兼容性测试（v0.1 镜像在 v1.0 工具链可用）→ registry 互操作（至少 2 个 OCI 实现）。

| 里程碑 | 验收标准 |
|---|---|
| M-S09-1（P1） | ethimg 三命令 + 验签攻击用例全过 |
| M-S09-2（P2） | RFC-001 v1.0 冻结 |
| M-S09-3（P3） | OCI push/pull 实测；索引服务上线 |

## 5. 可能的问题与快速查找关键词

| 问题 | 症状 | 搜索关键词 |
|---|---|---|
| OCI artifact media type 注册 | registry 拒绝 | `OCI artifact custom media type registry support`、`oras push custom artifact` |
| 嵌入式端验签性能 | 部署慢 | `monocypher Ed25519 RISC-V`（S05 已覆盖）；流式哈希（边收边算） |
| tar 格式嵌入式解析开销 | BMC 内存压力 | 固定顺序 tar + 边收边解；或自定义顺序块格式（评估后 ADR） |
| 版本语义混乱 | 用户困惑 | SemVer 强制 + lint；`semantic versioning spec` |
| 密钥丢失/轮换 | 无法更新官方镜像 | 密钥轮换流程文档；多签门槛（Phase 4） |

## 6. 实现守则速查
见 `../README.md` §2。所有示例镜像必须含完整 manifest 五件套（作为用户模板）。

## 7. 不确定时需向用户确认的问题
1. 镜像内是否允许携带多个 fabric 架构 target（加体积换兼容面）？
2. 官方镜像仓库命名空间策略（`ethereal-official/*` vs 用户命名空间）？
3. `.eth` 后缀与 tar 格式是否最终确认（替代：自定义顺序块格式，嵌入式更省）？
