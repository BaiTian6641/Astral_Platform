## 1. 是什么 / 做什么 / 重要度

平台的"神经系统"：对上提供 **I²C 监控通道**（PMBus 风格命令集，上位机/Astral 用 `i2cget` 就能读状态）；对内执行**健康管理**（region 看门狗、故障恢复策略、事件日志、遥测采集）；在 Zynq 上还负责 **SEU 配置存储器擦洗**的调度。

**为什么重要**：(1) 你指定的 I²C 监控通道就在这里落地；(2) "避免灾难性崩溃"的愿景在 FPGA 侧=看门狗+blank+restartPolicy；(3) 工业/车载客户买的就是健康审计与预测性维护能力——这是 Phase 5 商业故事的核心素材。

## 2. 大体规划

### 2.1 I²C 监控命令集（RFC-003 v1，PMBus 风格 + 厂商自定义区）

| 命令码 | 名称 | 语义 |
|---|---|---|
| 0x00 | PAGE | 选择 region/slot |
| 0x01 | OPERATION | on/off（=run/halt） |
| 0x79 | STATUS_WORD | 平台健康摘要 |
| 0x8B | READ_VCCINT | 内核电压（经 GW5 ADC / Zynq SYSMON） |
| 0x8D | READ_TEMPERATURE | 温度 |
| 0x98 | PMBUS_REVISION | 0x22（v1.2 风格声明） |
| 0xD0 | MFR_SLOT_STATUS | 当前 PAGE region 的状态/故障码/重构计数 |
| 0xD1 | MFR_EVENT_LOG | 事件环形缓冲读出 |
| 0xD2 | MFR_OCC_STATUS | OCC 状态（S02） |
| 0xD3 | MFR_RESTART | 触发 region 重启（带原因码） |
| 0xD4 | MFR_IMAGE_INFO | 当前镜像名/版本/digest 摘要 |

实现：BMC 的 NEORV32 TWD 外设 + 固件命令解释器；I²C target 支持 clock stretching（读遥测时给 ADC 转换留时间）。

### 2.2 健康策略

- **region 看门狗**：容器需按 manifest 声明周期写 HEARTBEAT（Region ABI CSR12）；超时→BMC 执行 STOPPING→BLANKING→按 `restartPolicy`（always/on-failure/never）处置；
- **事件日志**：BSRAM 环形缓冲（64 条：时间戳/region/事件/原因码），I²C 可读出，ethctl logs 可拉取；
- **分级响应**：fault 可恢复→重启容器；BMC 自身 WDT 触发→全 region blank + 安全态 + 事件上报（兜底）。

### 2.3 SEU 擦洗（Zynq 专属，Phase 3）

BMC 调度 SEM（或自研读回+比对）：周期读回配置帧→CRC/ECC 校验→ICAP 局部修复；包装成"slot 健康探针 + 自动重载"（类比 livenessProbe+restartPolicy）。Gowin 侧先评估读回可行性再排期。

## 3. 详细规划与阶段检查点

### Phase 1
| # | 步骤（任务 ID） | 检查点 |
|---|---|---|
| 1 | I²C 通道 v1（E1-IO2）：PAGE/STATUS_WORD/READ_VCCINT/MFR_SLOT_STATUS/MFR_OCC_STATUS | 树莓派 `i2cget` 读出 slot 状态；24h 轮询无锁死 |
| 2 | region 看门狗 v1（E1-RUN4，与 S02 联合） | 死锁镜像超时自动 blank，邻区无损 |
| 3 | 事件日志 v1（环形缓冲 + i2c 读出） | 注入 3 类故障，日志全部正确记录且可读出 |

### Phase 2
| # | 步骤 | 检查点 |
|---|---|---|
| 1 | 遥测 v1：GW5 ADC 温度/电压接入 | 读数与片外温度计/万用表比对误差报告 |
| 2 | restartPolicy 完整实现 + ethctl logs | 三种策略行为用例全过 |
| 3 | RFC-003 v1.0 冻结 | 命令集文档发布 |

### Phase 3
| # | 步骤 | 检查点 |
|---|---|---|
| 1 | Zynq SEM 擦洗集成（E3-MON1） | SEU 注入实验（SEM 注入口）自动修复演示 |
| 2 | 监控 v2：重构计数/温度历史/错误统计 | 历史曲线可经 ethctl 导出 CSV |

### Phase 4+
- 预测性维护（故障率统计、寿命报告）；SNMP/IPMI 风格网关（企业版素材）；与 Astral 健康面统一（容器+逻辑统一健康视图）。

## 4. 验证与里程碑验收

**方法**：命令集一致性测试（对上位机参考实现）→ 故障注入矩阵（看门狗/验签失败/OCC 错误/固件崩溃）→ 长稳测试（24h~72h 轮询）→（Zynq）SEU 注入实验。

| 里程碑 | 验收标准 |
|---|---|
| M-S07-1（P1） | i2cget 五命令可用；看门狗联动验收；24h 无锁死 |
| M-S07-2（P2） | RFC-003 v1.0；遥测误差报告；restartPolicy 全用例 |
| M-S07-3（P3） | Zynq SEU 注入自动修复演示 |

## 5. 可能的问题与快速查找关键词

| 问题 | 症状 | 搜索关键词 |
|---|---|---|
| I²C 多主/地址冲突 | 上位机读不到 | `I2C bus address collision troubleshoot`；manifest 声明地址并可配 |
| clock stretching 兼容性（树莓派缺陷） | 读超时 | `Raspberry Pi I2C clock stretching bug workaround`（缩短转换等待/分两次读） |
| GW5 ADC IP 用法 | 读数跳变 | `Gowin GW5AT X-channel oversampling ADC user guide` |
| Zynq SEM IP 许可/流程 | 工程报错 | `Xilinx SEM IP UltraScale evaluation license`、`PG187 SEM` |
| 事件日志掉电丢失 | 审计断链 | 关键事件镜像到板载 Flash（磨损均衡）；`embedded circular log flash wear leveling` |
| 看门狗误杀（合法长任务） | 容器被误重启 | manifest 声明心跳周期+宽限；`watchdog windowed timeout design` |
